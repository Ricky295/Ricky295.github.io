01 / How to contribute

One sensor.
A better picture.

You don’t need a professional weather station. A connected microcontroller or small computer and a temperature sensor are enough to start sharing useful local observations.

⌘
Microcontroller or SBC

ESP32, Raspberry Pi, or another Wi-Fi-capable board.

°
Temperature sensor

Any sensor your device can read and report in Celsius.

⌁
Wi-Fi connection

Send a reading to the API whenever your station measures.

＋
Humidity / pressure

Optional extras. Temperature is the only required weather value.

Getting started: create a station to receive its UUID and one-time password. Save both safely; use them to post readings. Public coordinates are rounded to four decimal places, and each reading is timestamped by the API.
02 / API reference

Small interface.
Useful weather.

Use the deployed web-app URL as the base. Public reads use GET; station creation, password-protected actions, and weather posts use POST with a JSON or form body.

Base URLhttps://script.google.com/macros/s/AKfycbxgESCuBN-ec_ZUpZAuT6MY7OwWGyb4Ew4hdGZ38Z30UCTc_6Do_zOPraKYOcjBkhhh/exec
GET · PUBLIC
?method=health
Simple availability check. Returns an `ok` status and service name.
POST · PUBLIC
?method=make_stationbody: {"lat":45.523,"lon":9.183}
Creates a station and returns its UUID plus a random 64-character password. Save the password immediately; it is shown only once.
POST · PASSWORD
?method=modify_stationbody: uuid, password, lat, lon
Changes coordinates for an existing station. Requires the station UUID and password.
POST · PASSWORD
?method=remove_stationbody: uuid, password
Removes the station. Existing weather rows are retained but public searches only include existing stations.
POST · PASSWORD
?method=station_infobody: uuid, password
Returns a station’s UUID and rounded coordinates. `method=info` is also accepted.
GET
?method=stations&lat=…&lon=…
Lists stations ordered from nearest to farthest from the supplied coordinates. Each result includes distance in kilometers.
GET
?method=search&max_distance=10&max_time_rollback=1.30&sort=recent&lat=…&lon=…
Finds readings from stations within `max_distance` km and the requested look-back window. `sort` is `recent` / `latest` or `nearest`; nearest sorts by distance, with newest first for ties. Response includes the station UUID.
GET
?method=data_from_station&station=<uuid>
Returns that station’s weather history, oldest first, with `count` and a `history` array. The station must still exist.
POST · PASSWORD
?method=post
Adds a weather reading. `uuid`, `password`, and `temp` are required; `hum` and `pre` are optional. Send credentials in the request body, never in the URL.
Search example
GET /exec?method=search&max_distance=10&max_time_rollback=1.30&sort=recent&lat=45.523&lon=9.183
Post example · JSON request body
POST /exec?method=post
Content-Type: application/json

{
          "uuid": "your-station-uuid",
          "password": "your-64-character-station-password",
  "temp": 25.5,
  "hum": 57.2,
  "pre": 923
}

Privacy: coordinates are rounded to four decimal places before storage and used for distance calculations. Time format: `max_time_rollback` uses traditional h.mm notation: `1.30` means 1 hour 30 minutes. Conversion: `int(d) + (d - int(d)) / .6`. All responses are JSON.

!

Save your station password when it is created

The API returns the 64-character password only once. Keep it private and send it in POST request bodies—not URLs. Public station listings still expose UUIDs and approximate locations, while public search and history expose weather readings. Four-decimal rounding is about 11 metres north-to-south; longitude precision varies with latitude.
